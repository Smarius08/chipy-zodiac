## User Inputs

The tool accepts:

* **First Name**
* **Date of Birth**

The **Reveal My Luck** CTA is active by default.

Validation occurs when the user clicks **Reveal My Luck**.

If one or both fields are invalid:

* Do not start the luck calculation.
* Keep the user on the form.
* Display the relevant error below each invalid field.

| Input | Behaviour | Error Condition | Error Message |
| --- | --- | --- | --- |
| **First Name** | Required. Accept A–Z letters. Uppercase and lowercase are treated the same for the calculation. | Field is empty | **Please enter a valid name** |
| **First Name** |  | Contains unsupported characters such as numbers or symbols | **Use A-Z letters only for your first name.** |
| **Date of Birth** | Required. Use the Material Design 3 Modal Date Picker. | Field is empty or contains an invalid date | **Please enter a valid date** |
| **Date of Birth** | Future dates and dates that make the user younger than the permitted minimum age must not be accepted. | Future or underage date | **Please enter a valid date** |

### Validation Behaviour

* Do not show errors when the form first loads.
* Clicking **Reveal My Luck** validates both fields.
* Show only the errors for invalid fields.
* If both fields are invalid, show both errors at the same time.
* Do not continue to the loading/result flow until both fields are valid.
* Remove a field's error state once the value becomes valid.

### Date Picker

Use the **Material Design 3 Modal Date Picker** and follow its documented interaction, navigation, date-selection and input behaviour.

Future dates and dates below the permitted minimum age must be unavailable.

If manual date entry is supported, apply the same validation rules.

**Minimum permitted age: 18.**

Modal Date Picker Documentation: https://m3.material.io/components/date-pickers/guidelines#:\~:text=Copy%20link-,Behavior,-Modal%20date%20pickers

## Determine the User’s Personal Values

From the valid user inputs, the tool determines:

* **Name Number** - number from 1–9 derived from the first name
* **Life Path Number** - number from 1–9 derived from the complete date of birth
* **Zodiac Sign** - determined from the month and day of birth
* **Zodiac Lucky Day(s)**
* **Zodiac Lucky Numbers**

The exact calculation rules and reference data are defined in **BFC-52418**.

---

## Determine Today’s Date Values

For **today’s date**, determine:

* **Date Number Total** — the total obtained by adding all digits in today’s date before reducing it to one number
* **Date Numerology Number** — the Date Number Total reduced to a number from 1–9
* **Day of the Week**

Example:

`22/02/2025 → 2+2+0+2+2+0+2+5 = 15`

Therefore:

`Date Number Total = 15`

Then:

`15 → 1+5 = 6`

Therefore:

`Date Numerology Number = 6`

---

## Apply the Four Scoring Rules

Use the user’s personal values and today’s date values to determine:

* **Name Score**
* **Life Path Score**
* **Lucky Day Score**
* **Lucky Number Score**

Add the four scores to produce the **Luck Score out of 10**:

`Luck Score = Name Score + Life Path Score + Lucky Day Score + Lucky Number Score`

Maximum:

`10`

The exact scoring rules are defined in **BFC-52418**.

---

## Compare Today With the Full Year

Perform the same scoring process for **every date in the current calendar year for that user**.

Rank all dates from strongest to weakest.

Today then receives an **Annual Rank**.

> **Annual Rank:** the position of today after all dates in that user’s year are ordered from strongest to weakest.

Use the Annual Rank to calculate the **Annual Luck Position**.

> **Annual Luck Position:** a percentage showing where today sits compared with all other dates in the same year for that user.

For example:

* `100%` = strongest date of the year
* `50%` = around the middle
* `0%` = weakest date of the year

The exact annual ranking, tie-break and Annual Luck Position calculations are defined in **BFC-52418**.

---

## Determine the Final Result

Use the **Annual Luck Position** to determine:

### Final Luck Category

One of:

* **Low Luck**
* **Some Luck**
* **Good Luck**
* **Jackpot Luck**

### Final Luck Score

A final score from:

`1.00 to 10.00`

The exact category boundaries and Final Luck Score calculation are defined in **BFC-52418**.

The calculation flow is:

**Four Scoring Rules → Luck Score → Annual Rank → Annual Luck Position → Final Luck Category → Final Luck Score**

## Daily Luck Reading Message

After the **Final Luck Category** is determined, select one **Daily Luck Reading Message** from the message pool matching that category.

| Requirement | Behaviour |
| --- | --- |
| **Category match** | Only use a message belonging to the user’s Final Luck Category. |
| **Messages per category** | Each Final Luck Category has 10 approved messages. |
| **Daily consistency** | The same user must receive the same message when checking again on the same day. |
| **Daily variation** | The selected message may change on another day. |
| **Selection basis** | Use the user’s first name + date of birth + today’s date to consistently select one of the 10 messages. |
| **Implementation** | Any deterministic method may be used as long as the same inputs return the same message for that day. Do not randomly select a new message on every page load. |

### Result CTA — Reset

After a valid result has been generated and the **Final Result** is displayed, show a **Reset** CTA.

When the user clicks **Reset**:

* Return the tool to the original **Form state**.
* Clear the First Name and Date of Birth fields.
* Clear the previous Luck Score, Final Luck Score, Final Luck Category and Daily Luck Reading Message.
* Clear any previous validation/error states.
* Return the crystal ball and surrounding assets to their original form-state treatment.
* Do not reload the page.

Flow:

**Final Result → Reset → Original Form**
