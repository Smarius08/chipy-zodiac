## Tool Flow / States

The tool must support the following flow:

`Form → Validate → Loading Animaiton → Score Reveal → Final Result`

The **Date Picker** is opened from the Date of Birth field when clicked.

### Validation

When **Reveal My Luck** is clicked:

* If the fields are valid → continue to Loading / Transition.
* If one or more fields are invalid → remain on the form and display the relevant Field Error state.

Do not reload or navigate to a separate page during the tool flow.

| State | Front-End Requirement |
| --- | --- |
| **Form** | Display the First Name, Date of Birth and active CTA inside the crystal ball. |
| **Date Picker** | Display the DOB date picker from the Date of Birth field. |
| **Field Error** | Display the appropriate inline error state for each invalid field. |
| **Loading Animation** | Replace the form content with the crystal-ball/zodiac animation shown in Figma. |
| **Score Reveal** | Reveal the calculated score as shown in the Figma sequence. |
| **Final Result** | Complete the transition into the relevant Low, Some, Good or Jackpot result state. |

---

## Form State

The initial form contains:

1. **Your First Name**
2. **Your Date of Birth**
3. **Reveal My Luck**

The form sits inside the crystal ball using the default purple visual treatment shown in Figma.

The **Reveal My Luck CTA is active by default**.

### First Name

Support:

* Normal state
* Empty-field error state
* Unsupported-name error state

Unsupported-name error message:

> **Use A-Z letters only for your first name.**

Empty-field error message:

> **Please enter a valid name**

The validation rules themselves are defined in **BFC-52417 — Tool Functionality**.

### Date of Birth

Display the calendar trigger shown in Figma.

Support:

* Normal state
* Empty/invalid-date error state

Error message:

> **Please enter a valid date**

The DOB validation rules are defined in **BFC-52417**.

## Error States

Errors are shown **after the user clicks Reveal My Luck**.

Each field must support its own error state independently.

The error presentation must include:

* Error border/state on the affected input
* Error indicator/icon
* Inline error text directly beneath the affected input

If both fields are invalid, display both errors at the same time.

Do not proceed to the transition and result state while validation errors remain.

The rules that determine when each error appears are defined in:

**BFC-52417 — Tool Functionality**

## Final Result Layout

There is **one result structure** shared by all four Final Luck Categories.

Display:

* **Final Luck Score** with `/10`
* **Final Luck Category**
* **Daily Luck Reading Message**
* Result CTA shown in Figma
* **Zodiac**
* **Lucky Day(s)**
* **Lucky Numbers**
* Tool disclaimer

Display the **Reset** CTA in the Final Result state as shown in Figma. Its reset behaviour is defined in **BFC-52417 — Tool Functionality**.

### Category Visual Treatments

Each Category is color coded.

| Final Luck Category | Colour Treatment | Matching Visual Assets |
| --- | --- | --- |
| **Jackpot Luck** | Teal / cyan glow with purple and pink highlights | Jackpot hand and crystal-ball/orb assets |
| **Good Luck** | Blue / electric-blue glow with purple and pink highlights | Good Luck hand and crystal-ball/orb assets |
| **Some Luck** | Purple / magenta glow with pink highlights | Some Luck hand and crystal-ball/orb assets |
| **Low Luck** | Red / burgundy glow with pink and purple highlights | Low Luck hand and crystal-ball/orb assets |

Use the **exact category colours and assets supplied in Figma** → https://www.figma.com/design/mRGsMU76MmiKMnzQkwYKgG/Tools---Calculators?node-id=11809-102658&t=vmOb6U2oyZj07wdB-1 

The structure remains the same across all categories. The calculated score, category-specific content and category visual treatment change.

## Responsive Layout

Use the supplied Figma designs as the source of truth for each viewport. The composition must adapt rather than simply scaling the desktop design down.

| Viewport | Layout Requirement |
| --- | --- |
| **Desktop** | Centre the crystal ball with one hand on each side. Display supporting result information horizontally beneath the main result. |
| **Tablet — 768px portrait** | Retain the side-hand composition, resizing and repositioning the hands and crystal ball according to Figma. |
| **Tablet — 600px portrait** | Change to the vertical composition with one hand above and one below the crystal ball. Allow the title/content to wrap as shown in Figma. |
| **Mobile** | Use the dedicated vertical composition with hands above/below the crystal ball. Stack supporting result information vertically. |

### Implementation Notes

* Apply the appropriate composition to the Form, Loading/Transition and Result states.
* Follow the supplied Figma positioning and proportions at each viewport.
* Transition responsively from the side-hand layout to the top/bottom-hand layout rather than continuously shrinking the desktop assets.
* Keep text, inputs, CTA, messages and result information fully visible and clear of the artwork.
