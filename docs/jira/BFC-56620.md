This tool should be protected from being copied by our competitors! See related task: [BFC-52392](https://gtmarketing.atlassian.net/browse/BFC-52392)

Reuse **BFC-52417** as built: inputs, validation, calculation, result, Daily Luck Reading Message and Reset. The calculation stays in PHP (BFC-54160). **The date picker works differently on sign pages** (see below).

The tool’s visual design is in [BFC-56619](https://gtmarketing.atlassian.net/browse/BFC-56619).

#### Info strip

On page load, the info strip (Zodiac, Lucky Day(s), Lucky Numbers) shows the page’s sign. It’s filled in the HTML, using the values in the table below.

#### Date of Birth: date picker

This is the same Date Picker as in BFC-52417. It has two modes, and the user switches between them with the pencil icon. Figma: \[TBD\]

**Calendar mode: only the sign’s dates can be selected**

* Only dates inside the page’s sign range can be selected (table below). All other days use the disabled date state.

    * Example: on the Aries page, only Mar 21 – Apr 19 can be selected, in any allowed year.
    
* The month arrows move only between the sign’s months.

    * Aries: March and April.
    * Capricorn: December and the following January.
    
* Year selection shows every year the age rule allows.
* The picker opens on the sign’s first month, in the latest year the age rule allows.
* The age rules are unchanged: no future dates, and a minimum age of 18.
* On the Pisces page, Feb 29 can be selected in leap years.

**Input mode: any date can be typed (dd/mm/yyyy)**

* When the user clicks OK, the BFC-52417 checks run first: a valid date, not in the future, and age 18 or over. Those checks and their errors are unchanged.
* If those checks pass but the date falls under a different sign, the date is not accepted. The picker stays open and shows this error under the input:

    This date falls under \[Sign\]. Go to the \[Sign\] tool.



    * \[Sign\] is the sign the typed date falls under.
    * The words “\[Sign\] tool” are a link to `/tools/[sign]-lucky-days-to-gamble`, opening in the same tab.
    * The user can correct the date, follow the link, or click Cancel.
    * On the page the link opens, the user enters their details again. Nothing is carried over.
    * Example: on the Aries page, typing 01/08/1990 shows “This date falls under Leo. Go to the Leo tool.”, linking to `/tools/leo-lucky-days-to-gamble`.
    
* If the date falls under the page’s sign, OK fills the Date of Birth field as usual.

Clear, Cancel and OK work as in BFC-52417.

#### Error messages

These appear under the fields after the user clicks **Reveal My Luck**, as in BFC-52417:

* “Please enter a valid name” (First Name is empty)
* “Use A-Z letters only for your first name.” (First Name has numbers or symbols)
* “Please enter a valid date” (Date of Birth is empty or invalid)

If both fields are invalid, both errors show at the same time.

The zodiac mismatch error appears only inside the date picker, in input mode. The picker never accepts another sign’s date, so this error never appears under the Date of Birth field.

#### Result and Reset

* **Result:** as in BFC-52417. The info strip shows the values returned for the user’s birth date. Because the picker only accepts the page’s sign, this is always the page’s sign.
* **Reset:** as in BFC-52417. The tool returns to the sign’s form-state treatment (visuals in BFC-56619), and the info strip shows the page’s sign again.

The sign sections below the tool are in [BFC-56633](https://gtmarketing.atlassian.net/browse/BFC-56633) (layout) and [BFC-56885](https://gtmarketing.atlassian.net/browse/BFC-56885) (functionality).
