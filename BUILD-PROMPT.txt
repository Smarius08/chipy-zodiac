6. PERSONAL TOOL — REQUIRED STATES AND DATE PICKER
One shared UI/state implementation across signs:
Initial Form → Validate → Loading/Transition → Score Reveal → Final Result.
Request failure → Form with preserved inputs and request error.
Reset → original empty form, without reload.

Initial:
- First Name, Date of Birth and active “Reveal My Luck”.
- No initial errors.
- Info strip is filled with the page’s sign, Lucky Day(s) and Lucky Numbers on initial HTML load.
- Both invalid fields show their own errors simultaneously after submit.
- Empty name: “Please enter a valid name”
- Unsupported name: “Use A-Z letters only for your first name.”
- Empty/invalid DOB: “Please enter a valid date”
- A–Z-only first name; no new normalization or international-input behavior.
- No submission while invalid; prevent duplicate pending submissions.

Sign-specific Material Design 3 modal DOB picker:
- Calendar and manual input modes, with pencil/calendar switching.
- Calendar permits only that sign’s date range in allowed years. Disable all other dates.
- Month arrows navigate only the sign’s months.
- Capricorn crosses December and the following January. Do not mishandle the year transition.
- Year selection includes all years permitted by the age rule. Open at the sign’s first month in the latest age-allowed year; do not enable underage days within it.
- No future dates; minimum age 18, evaluated against the local date.
- Pisces Feb 29 is selectable in leap years.
- Manual input uses dd/mm/yyyy and allows typing any date.
- On OK, validate real Gregorian date, future restriction and age FIRST.
- Only if those pass, reject a DOB outside the page’s sign. Keep picker open. Show under its manual input:
  “This date falls under [Sign]. Go to the [Sign] tool.”
- Only “[Sign] tool” is linked, to /tools/[sign]-lucky-days-to-gamble, in the same tab.
- No carry-over of name or DOB to the destination.
- Example: Aries page + 01/08/1990 → “This date falls under Leo. Go to the Leo tool.”
- This mismatch error belongs only inside manual picker mode, never under the main form DOB field.
- Clear, Cancel and OK work correctly; Cancel does not apply an unconfirmed change.
A native date input alone does not reproduce these required interactions.

Request failure:
- Stop loading, restore form, preserve valid inputs.
- Below CTA: “Something went wrong. Please try again.”
- Retry via Reveal My Luck; no extra Retry button; no stale previous result.

Result:
- Final Luck Score with /10, Final Luck Category, matching personal Daily Luck Reading Message, Reset, info strip and disclaimer.
- Keep category treatments independent of the selected sign: Low red/burgundy; Some purple/magenta; Good blue; Jackpot teal/cyan.
- Use actual Figma category assets/colours where provided.
- Use BFC-52417’s 40 approved PERSONAL messages, ten per category; these are not the 48 sign messages.
- Same user/date receives the same personal message via a deterministic backend response/fixture, never fresh randomness.
- Reset clears all input, result, error and pending state and restores the selected sign’s initial theme/strip without reload.
- Full message remains inside the ball without overlapping artwork or Reset at desktop, 768, 600 and mobile.
