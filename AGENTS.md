# Project operating rules
Read CLAUDE.md, BUILD-PROMPT.txt and docs/CURRENT-REQUIREMENTS.md.
Use the user's source hierarchy: 02_CURRENT_JIRA_SPECS for requirements/ownership; 03_CALCULATION_MODEL for personal math; 04_UI_UX_AND_STATES for shared states; 06_ZODIAC_EXPANSION for expansion; 07_OPEN_ITEMS_AND_QA for gaps/QA; 01_PROJECT_HANDOFF for context; 05_DECISION_HISTORY for history only.
These files are preserved unchanged under docs/handoff/. Current explicitly agreed requirements from November Jira snapshots supersede their historical TBDs as documented in docs/CURRENT-REQUIREMENTS.md. If a current-source conflict cannot be resolved, quote it and ask for the decision.
Figma controls visual presentation only. Do not infer missing scoring, age, routing, backend or error requirements. Do not create hybrid old/new calculations.
Canonical terms: Date Number Total, Date Numerology Number, Luck Score, Annual Rank, Annual Luck Position, Final Luck Category, Final Luck Score, Reference Data, Four Scoring Rules.
One shared backend engine with personal and sign-level paths; no browser scoring and no 12 separate engines. Today means visitor-local calendar date.
Personal request failure returns to the form preserving inputs. Reset clears inputs/results/errors and restores the selected sign's empty form without reload.
Distinguish current requirement, problem, proposed change and affected Jira/files. Never claim a proposal is approved.
